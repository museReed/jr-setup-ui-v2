# VM 檢查表

每張卡做完、以及每次要發給學生之前，在乾淨的 VM 上照這份跑一次。

**為什麼需要它**：2026-08-11 那一輪 VM 驗收挖出九個問題，**沒有一個被單元測試擋住**——它們全是
「這台機器上的東西被怎麼叫」的問題（PATH 快照、執行原則、shell 轉譯、工具名字），而測試跑在
一台已經裝好一切的開發機上。

**怎麼用**：每一項都是「做什麼 → 看到什麼算過 → **壞掉時長什麼樣**」。第三欄最重要——2026-08-11
那輪在同一個現象上繞了三輪，因為 PowerShell 的剖析錯誤長得很像「有被擋」。

一份檔案、三段：共通的做兩次（兩個平台各一次），另外兩段各自只做一次。

---

## 0. 起跑

| 平台 | 指令 |
|---|---|
| macOS | `bash -c "$(curl -fsSL https://raw.githubusercontent.com/museReed/jr-setup-ui-v2/main/docs/setup.sh)"` |
| Windows | `irm https://raw.githubusercontent.com/museReed/jr-setup-ui-v2/main/docs/setup.ps1 \| iex`（PowerShell，不是 CMD） |

驗還沒 merge 的分支：macOS 前面加 `JR_BRANCH=<branch>`；Windows 前面加 `$JrBranch="<branch>";`。
跑起來後確認抓的是哪一份：`cat ~/.jr-setup-v2/app/.jr-source`（Windows：`type $HOME\.jr-setup-v2\app\.jr-source`）。

要直接跳到第 N 張卡：`http://localhost:7430/?card=<卡片 id 或第幾張>`（例：`?card=codex`、`?card=2`）。

⚠️ **VM 上不要設 `JR_FAKE_ENV`**。假環境只蓋它認得的那幾格，設定檔那幾格仍走真的探測——半真半假的
畫面比全假更難判讀。

## 1. 共通（兩個平台都要跑）

- [ ] **第一次開頁是「未安裝」態**
  - 過：每一格都寫「還沒安裝」，安裝鍵畫得出來。
  - 壞掉：開發機上永遠看不到這一態（那台什麼都裝好了）——所以這一項只有乾淨 VM 驗得到。

- [ ] **裝完那一格會自己變綠，不用重開嚮導**
  - 過：按安裝 → 跑完 → 那一格從「還沒安裝」變成「裝好了，還沒驗過真的生效」。
  - 壞掉：終端印著 `Installation complete!`，格子卻還是紅的（#14）。原因是嚮導那個行程的 PATH 是
    啟動當下的快照，看不到安裝器剛寫進去的目錄。

- [ ] **登入那一列的連結點得開**
  - 過：按登入 → 畫面出現授權連結 → 點下去瀏覽器開得起來。
  - 壞掉：連結帶著色碼（`ESC[36m…`）變成打不開的網址（見 `findAuthLink`）。

- [ ] **貼授權碼送得出去**
  - 過：貼進輸入框按送出，終端區回顯 `> <你貼的碼>`，登入繼續往下走。
  - 壞掉：什麼反應都沒有——少一個換行時 CLI 會一直等（那是 2026-08-10 的 bug）。

- [ ] **「開終端驗證」的視窗裡叫得動那支 CLI**
  - 過：視窗印出版本號，按 Enter 關掉後網頁那一格變綠。
  - 壞掉：視窗裡是 `command not found` / `is not recognized`（#20）。

- [ ] **驗到一半關掉視窗，網頁不會卡死**
  - 過：那一格回到未驗證，按鈕拿得回來，可以再按一次。
  - 壞掉：每顆按鈕灰著等三分鐘。

- [ ] **伺服器不會因為單一次失敗整個掛掉**
  - 過：驗證跑完（不管過不過），後面每顆按鈕都還能按。
  - 壞掉：按什麼都沒反應，而網頁還在——去看跑伺服器那個視窗，通常有一段沒人接的例外（#24）。

- [ ] **攔截器那一格：真的被我們的 hook 擋下**
  - 過：副產物／畫面上出現**中文**「一次只跑一個指令」。
  - 壞掉的三種長相，要分得出來：
    - `Failed with non-blocking status code: <我們的訊息>` → hook 有跑，但它回的決定沒被當成擋下（#38）。
    - 兩個 echo 都跑掉、沒有任何錯誤 → hook 根本沒被叫（matcher / 註冊，#34、#26）。
    - shell 自己的剖析錯誤 → 那是 shell 擋的，不是我們（#32）。

- [ ] **白名單那一格：四件事都沒跳「要不要允許」**
  - 過：`echo` / `pwd` / `git status` / WebFetch 四步都直接跑掉。
  - 壞掉：其中一步跳出允許提示——題目叫學生不要按允許，所以會停在那裡（#36）。

- [ ] **切語言之後，跑起來的訊息也跟著翻**
  - 過：切成 English 後按任一顆按鈕，終端區的白話進度是英文。
  - 壞掉：卡片標題變英文、終端區仍是中文——伺服器產生的字沒有走代號（issue #11，已知未修）。

## 2. macOS 專屬

- [ ] **安裝不經過 npm**
  - 過：`ps -ef | grep -c "[c]laude.ai/install.sh"` ≥ 1，整條命令列裡沒有 npm。
  - 壞掉：npm 那條在 macOS 上會撞 EACCES（乾淨 VM 實測，見 `installers.ts` 開頭）。

- [ ] **claude 補 PATH、codex 不補**
  - 過：裝完 claude 後 `~/.zshrc` 多一行 `export PATH="$HOME/.local/bin:$PATH"`；裝完 codex 後
    `~/.zprofile` 有 codex 自己寫的那段，而 `~/.zshrc` **沒有**因為 codex 多出第二行。
  - 壞掉：兩支都補 → 重裝時長出重複的 PATH 行。

- [ ] **codex 安裝不會停在問句**
  - 過：安裝一路跑完。
  - 壞掉：畫面停在「安裝中」不動——安裝器問「Start Codex now?」寫在 `/dev/tty`，印在學生沒在看的
    終端機（靠 `CODEX_NON_INTERACTIVE=1` 擋掉）。

- [ ] **codex 登入會自己開瀏覽器**（這是預期，不是 bug）
  - 過：瀏覽器自己跳出來；沒跳的話畫面上的備援連結點得開。

- [ ] **Claude Code 的全螢幕那三格**
  - 過：方框跳出來能按 1、滑鼠點得動游標、圈選代碼貼回欄位後自動打勾。
  - 壞掉：貼回去沒反應 → 比對的字串對不上（`FULLSCREEN_PROOF`）。

## 3. Windows 專屬

⚠️ **這一段每一項都對應一個 2026-08-11 真的踩到的坑。**

- [ ] **bootstrap 跑得完**
  - 過：Node 檢查 → 下載 → install + build → 瀏覽器自己開起來。
  - 壞掉：`npm.ps1 cannot be loaded because running scripts is disabled` → 執行原則擋掉 `.ps1`，
    要叫 `npm.cmd`（#16）。

- [ ] **在同一個視窗重貼一次安裝指令**
  - 過：順利重裝。
  - 壞掉：`Cannot remove the item ... because it is in use` → 那個視窗正站在要被刪的資料夾裡（#22）。

- [ ] **winget 的進度動畫沒有淹掉原始輸出**
  - 過：按 Python / git / gh 安裝時，「看原始輸出」是看得懂的幾十行。
  - 壞掉：幾百行 `- \ | /`（#18 的過濾器要生效）。

- [ ] **登錄檔的 PATH 有被重讀**
  - 過：winget 裝完那一格自己變綠。
  - 壞掉：明明裝好了還是紅的——winget 寫的是登錄檔，跑著的行程看不到（#14）。

- [ ] **開出去的終端視窗也吃得到新 PATH**
  - 過：「開終端驗證」的視窗印得出版本號。
  - 壞掉：`claude : The term 'claude' is not recognized`（#20）。

- [ ] **`.ps1` 的中文沒有變亂碼**
  - 過：驗證視窗裡的中文提示讀得懂。
  - 壞掉：亂碼，甚至整支腳本 parse 不過——PowerShell 5.1 沒有 BOM 就當系統 ANSI 讀。

- [ ] **hook 對「模型走哪條路」都成立**
  - Windows 上 Claude Code 有**兩個**跑指令的工具（Bash / PowerShell），**選哪個是模型自己決定的**。
  - 過：不管畫面上顯示哪一種，都出現中文「一次只跑一個指令」。
  - 怎麼確認它走了哪條：看轉錄裡的 `PreToolUse:<工具名>`，或指令有沒有被包上 `$PSStyle...` 前綴。
  - 壞掉：見共通段「攔截器」那三種長相。

- [ ] **白名單兩條路都涵蓋**
  - 過：安裝白名單那格顯示「新增 82 條規則」（39 條 Bash + 43 條 PowerShell）。
  - 壞掉：只有 39 條 → win32 那份沒被發（#36），模型走 PowerShell 時一條都命中不了。

- [ ] **PowerShell profile 裡的包裝函式沒有吃掉旗標**
  - 過：驗證視窗開出來的 claude 行程參數裡看得到我們加的旗標。
  - 壞掉：macOS 上實測過包裝函式會把 `--permission-mode` 吃掉；Windows 這半還沒驗過。

## 4. 回報格式

貼回來的東西要能判讀，所以：

- **完整截圖，不要裁**。2026-08-10 有一輪因為兩張各裁掉一半的截圖，判定成「輸入列沒渲染」，
  其實它一直都在，白花三四輪。
- 失敗時**同時**給：網頁那一區的字、跑伺服器那個視窗的輸出、以及開出去那個終端視窗的內容。
  三個地方各講一半的事。
- 講得出「你按的是哪一列」——擋下的判斷是逐格的。
